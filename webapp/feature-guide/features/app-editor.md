The App Builder is where a Kindredly app's code lives. Build your own, edit the code, watch the
preview update, and save back to the item. The assistant beside it can write the code for you.

Apps you make live in your library like anything else you save, which is also how they reach your
Launchpad.

## Turning it on

App Builder needs two things: **Advanced mode**, and the App Builder switch itself.

Advanced mode is one switch at the top of **Settings → Manage Features**. It is off by default and
follows you across your devices. Writing code is the deepest end of Kindredly, so it stays out of
the way until you say you want it.

App Builder is experimental and starts off for everyone. Turn it on for yourself under
**Settings → Manage Features → Experimental features**, or with the switch above.

To let a child build apps, choose them under "Applies to" and turn it on for them. Only a parent
can do that.

With it off there is no App Builder tile, no **App builder** button on an app's item page, and
"Kindredly App" isn't offered when you add something new. **Apps still run** — turning off building
never stops anyone using an app someone built for them. It hides the way in rather than sealing it;
what keeps a child out of other people's apps is that they can only write to their own items.

## How to use it

1. Open the **App Builder** from the Launchpad, or from **App builder** on an app's item page.
2. Pick an app to work on, or choose **New app**.
3. Edit the code directly, or describe the change you want in the assistant panel.
4. **Run** shows your current code — unsaved edits included — in the preview pane; the button
   beside it runs the same code full screen. Saving writes back to the item.

Apps someone else built, added to your library from the apps directory, are not listed. Their code
lives with the app rather than in your copy, so there is nothing here to open — they still run
normally.

## Notes

Experimental. The builder is included; the AI assistant is a Plus feature.

In the browser extension the builder runs through the hosted webapp, because the compiler it needs
isn't packaged with the extension.
